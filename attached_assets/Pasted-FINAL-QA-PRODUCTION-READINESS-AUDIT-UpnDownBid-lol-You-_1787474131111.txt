==================================================
1. PRODUCT CORE
==================================================

UpnDownBid is a public weekly ranking marketplace where:

- Website/app owners can submit their website/app.
- Each product belongs to a category.
- A campaign runs for exactly 7 days.
- The campaign starts fresh every week.
- Products compete based on their effective bid.
- Users can bid/support products.
- Users can apply monetary penalties to products.
- Support increases effective bid.
- Penalties decrease effective bid.
- The highest effective bid ranks #1.
- At the end of the campaign, the highest-ranked product becomes that week's winner.
- Previous winners must remain stored historically.
- The previous week's winner must remain prominently visible as the latest winner.
- A new weekly campaign starts fresh while preserving historical records.

==================================================
2. PRODUCT SUBMISSION
==================================================

Test the complete "Add Product" flow.

The user must be able to:

1. Enter a valid website/app URL.
2. Select a category.
3. Enter/select the initial bid.
4. See the projected ranking.
5. See the current #1 bid.
6. See exactly how much is required to reach #1.
7. Submit the product.

Rules:

- URL must be validated.
- Invalid URLs must be rejected gracefully.
- Duplicate products/URLs must be handled correctly.
- The same product should not accidentally create duplicate listings.
- Category is required.
- Minimum initial bid is $5 unless the existing business rules explicitly specify otherwise.
- If the current #1 is $250, a new product paying $250 should be handled according to the existing tie/ranking rule.
- If the user wants to claim #1 and the current effective bid is $250, the UI must clearly communicate the required amount.
- Projected rank must be calculated from the real current ranking data.

4. EFFECTIVE BID CALCULATION
==================================================

Verify the calculation from the database/server side.

Effective bid should follow the existing intended model:

OWNER BID
+ COMMUNITY SUPPORT / BIDS
- PENALTIES
= EFFECTIVE BID

Example:

Owner bid = $180
Community support = $119
Penalties = $22

Effective bid = $277

Do NOT trust client-side calculations.

The authoritative calculation must happen server-side.

Prevent:

- Negative effective bids unless intentionally supported by the business rules.
- NaN values.
- Decimal/rounding bugs.
- Negative bid values.
- Negative penalty values.
- Invalid currency values.
- Client manipulation.
