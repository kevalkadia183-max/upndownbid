PHASE 13 — PAYMENT INTEGRATION
==================================================

ONLY AFTER PHASE 12 PASSES.

Inspect the existing payment implementation first.

If the project already contains a payment provider integration/configuration, continue using that provider rather than introducing another provider unnecessarily.

The existing Upndownbid checkout design has previously used Polar-style checkout, so inspect the current implementation before deciding whether Polar or another provider is already wired into the application.

Do NOT blindly replace existing payment infrastructure.

Payment requirements:

1. User chooses a Boost amount.
2. Show the product being boosted.
3. Show campaign number.
4. Show current highest effective bid.
5. Show the user's proposed amount.
6. Show amount required to reach the desired ranking.
7. Clearly state that the payment is for the campaign action.
8. User confirms.
9. Payment provider checkout opens.
10. Payment succeeds.
11. Server verifies the payment.
12. Server records the payment.
13. Server updates the authoritative bid/ledger.
14. Leaderboard updates atomically.
15. User receives confirmation.

Payment must be server-authoritative.

NEVER trust:
- frontend payment success
- frontend amount
- frontend ranking
- frontend product ownership
