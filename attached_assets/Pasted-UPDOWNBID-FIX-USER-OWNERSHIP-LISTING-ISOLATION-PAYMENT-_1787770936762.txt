UPDOWNBID — FIX USER OWNERSHIP, LISTING ISOLATION, PAYMENT STATE, AND OWNER PROFILE EDITING

I found several account-isolation problems during testing. Fix them properly without breaking the existing PayPal, Google authentication, campaign, ranking, or admin functionality.

IMPORTANT:
Do NOT just hide UI elements.
Fix the underlying database ownership, authorization, pending-checkout, and profile persistence logic.

==================================================
BUG 1 — LISTING CREATED BY ONE USER APPEARS AS OWNER/PAYMENT STATE FOR ANOTHER USER
==================================================

I created a listing using a separate test email/account.

That listing is visible from another account/admin account.

Public listings are supposed to be visible to everyone, so PUBLIC VISIBILITY IS NOT THE PROBLEM.

The problem is that account-specific owner/payment state is leaking between users.

Example:

User B creates/submits listing:

listing.ownerUserId = User B

User A/Admin logs in.

User A/Admin must NOT receive User B's:

- pending checkout
- payment retry
- claim state
- owner state
- private profile state
- ownership controls
- payment session
- checkout intent

Admin may see the listing because Admin has administrative visibility, but Admin must not become the owner of that listing.

==================================================
2. LISTING OWNERSHIP MUST BE EXPLICIT
==================================================

Inspect the listings/products schema.

Every owner-created listing must have a permanent owner identity such as:

ownerUserId

or the existing equivalent.

It must reference the authenticated user's internal ID.

DO NOT use:

- email as the primary ownership key
- browser localStorage as ownership
- a global variable
- current admin user
- listing slug alone
- website URL alone

Ownership must be based on the authenticated account/user ID.

When User B creates a listing:

listing.ownerUserId = authenticatedUser.id

When User A views the listing:

listing.ownerUserId remains User B.

Never overwrite it simply because another authenticated user is viewing the listing.

==================================================
3. PUBLIC LISTING VS OWNER ACCESS
==================================================

Separate these concepts:

PUBLIC VISIBILITY
and
OWNER ACCESS.

A public visitor can see:

- listing
- product name
- website/domain
- category
- ranking
- boosts
- push downs
- click count
- public information

But only the actual owner can access:

- edit product
- owner profile controls related to their account
- private payment history
- owner checkout state
- owner receipts
- owner dashboard data
- private listing management

Admin can access/manage listings through explicit ADMIN authorization.

Do NOT treat Admin as the owner.

4. FIX "TRY PAYMENT AGAIN" LEAK
==================================================

The screenshot shows:

"Your account is ready. We couldn't start payment yet. Try payment again."

This type of payment state MUST be scoped to the authenticated user and the specific checkout intent.

Do not display another user's pending payment to Admin or another account.

Pending checkout must be associated with:

userId
+
listingId
+
campaignId
+
intentId

For example:

pendingCheckout.userId = authenticatedUser.id

When loading pending checkout:

WHERE
pendingCheckout.userId = currentAuthenticatedUser.id

AND
pendingCheckout.status = pending

AND
pendingCheckout.expiresAt > now

Do NOT query pending checkout globally by listing slug alone.

Do NOT query only by listingId.

Do NOT query only by action type.

Do NOT use a global pending checkout object.

5. FIX PAYMENT RETRY
==================================================

"Try payment again" must only appear if:

- the current authenticated user owns the pending checkout OR legitimately initiated that checkout
- the checkout belongs to the current user
- the listing/campaign still exists
- the campaign is still active
- the checkout has not expired
- the payment has not already succeeded

If the current user did NOT create the checkout:

DO NOT show:

"Try payment again"

Instead show the normal public listing state.
