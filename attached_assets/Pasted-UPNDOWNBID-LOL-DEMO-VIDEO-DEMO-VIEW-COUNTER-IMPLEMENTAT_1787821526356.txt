IMPORTANT:
Do NOT redesign the existing application.
Do NOT remove or change existing ranking, campaign, bidding, payment, boost, push-down, review, authentication, or admin functionality.

Use the existing UI, typography, spacing, colors, cards, icons, responsive behavior, and component architecture.

==================================================
1. DEMO VIDEO — LISTING DATA
==================================================

Add an optional Demo Video URL to every listing.

The field must be OPTIONAL.

Supported examples:
- YouTube
- YouTube Shorts
- Vimeo
- Other valid video URLs if the existing architecture supports them

Recommended database field:

demo_video_url TEXT NULL

Existing listings must remain valid when demo_video_url is NULL.

DO NOT require every listing to have a demo.

If no demo exists:
- Do not show an empty video box
- Do not show "No demo"
- Do not show a broken player
- Simply hide the demo UI

==================================================
5. DEMO VIEW COUNTER
==================================================

Create persistent demo view tracking.

Recommended fields:

listings.demo_view_count INTEGER NOT NULL DEFAULT 0

However, do NOT simply increment the number every time someone repeatedly clicks the button.

The displayed number should represent PEOPLE/VISITORS who watched the demo as reasonably as possible.

Use the existing visitor/session tracking architecture if available.

Recommended behavior:

- First meaningful demo watch by a visitor/session = +1
- Repeated opening by the same visitor/session within a reasonable period should NOT continuously inflate the count.
- Do not require login to count a demo view.
- Do not expose visitor IP addresses or other private information publicly.

If the existing application already has anonymous visitor/session tracking, reuse it instead of creating a second unrelated tracking system.

==================================================
6. CREATE DEMO VIEW TRACKING ENDPOINT
==================================================

Add a secure backend endpoint, for example:

POST /api/listings/:listingId/demo-view

The endpoint should:

1. Verify the listing exists.
2. Verify that the listing has a demo URL.
3. Register a demo view using the existing visitor/session mechanism.
4. Prevent obvious duplicate counting from the same visitor/session.
5. Increment the demo view count safely.
6. Return the updated count.

Example response:

{
  "success": true,
  "demoViews": 129
}

Do not trust a client-provided counter.

The server/database must be the source of truth.

Prevent race conditions when multiple visitors watch simultaneously.
