FIX THIS EXACT FLOW — GOOGLE LOGIN MUST REDIRECT DIRECTLY TO PAYMENT

The required user flow is:

1. User selects a listing.
2. User chooses the claim amount.
3. User clicks the claim/start action.
4. If not logged in → open Google login.
5. User completes Google login.
6. Authentication/session is established.
7. IMMEDIATELY redirect the user to the PAYMENT CONFIRMATION PAGE for the claim they just started.
8. User sees:
   - Listing
   - Campaign
   - Claim amount
   - Total charged today
   - Refund & Cancellation Policy
   - CONFIRM AND PAY
9. User confirms and proceeds to PayPal.

The redirect after successful Google authentication MUST NOT go to:

- homepage
- discover page
- listing page
- claim form
- portal
- account page

It MUST go directly to the pending payment/checkout page.

Expected:

CLAIM
↓
GOOGLE LOGIN
↓
AUTHENTICATION SUCCESS
↓
PAYMENT PAGE
↓
CONFIRM AND PAY
↓
PAYPAL

NOT:

CLAIM
↓
GOOGLE LOGIN
↓
HOMEPAGE
↓
REFRESH
↓
PAYMENT

Fix the actual authentication callback/navigation logic.

==================================================
PENDING CLAIM
==================================================

Before sending the user to Google login, create/preserve a secure pending checkout intent containing the necessary claim context, such as:

- listing ID
- listing slug
- campaign ID
- action type
- requested amount
- intent ID
- creation/expiry time

After Google authentication:

1. Establish the authenticated session.
2. Retrieve the pending checkout intent.
3. Validate it server-side.
4. Confirm the campaign is still active.
5. Confirm the listing still exists.
6. Recalculate/verify the authoritative amount.
7. Navigate DIRECTLY to the checkout/payment confirmation page.

Use the existing checkout architecture if already present.
